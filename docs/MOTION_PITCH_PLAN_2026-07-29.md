## 3. 아키텍처

### 3.1 렌더러 — 브라우저를 합성기로

직렬화 가능한 `PitchScene` JSON이 **유일한 계약**이고, JSON→픽셀 구현은 React 컴포넌트 **하나**뿐이다.

```
PitchScene JSON  ──┬──▶ 브라우저에서 실행           → 웹 플레이어 (공개 URL, Dater 미리보기)
                   └──▶ headless Chromium 프레임 캡처 → FFmpeg 인코딩 → MP4 (다운로드)
```

**FFmpeg는 합성기가 아니라 인코더 + 업로드 클립 정규화기다.** 근거(전부 Opus-R 실측):

- 브라우저 합성 0.92 CPU-s/video-second vs FFmpeg 0.73 — **1.26배 차이뿐**. "FFmpeg가 훨씬 싸다"는 통념이 이 워크로드에서 깨진다.
- 로컬 ffmpeg 8.1.2 빌드에 `drawtext`도 `subtitles`도 없다(freetype/harfbuzz/libass 미포함). 텍스트를 브라우저로 그릴 거면 프레임 전체를 브라우저로 그리는 게 맞다.
- headless Chrome `<video>` seek 드리프트 **0ms**. C7(사진+영상 혼합)의 기술적 관문이 통과됐다.

### 3.2 인제스트 프록시 — 하나의 산출물로 다섯 문제를 동시에 푼다

업로드된 영상을 **1080x1920 / 30fps / h264 / GOP=15 / 무음** 프록시로 정규화한다.
이 하나가 fps 불일치, 코덱 불일치, 방향, 오디오 충돌, 모더레이션 대상 확정을 동시에 해결하고,
**웹과 렌더가 문자 그대로 같은 파일을 소비**한다. seek 비용도 GOP 재인코딩으로 102.7ms → **38.5ms/frame(2.7배)**로 떨어진다.

### 3.3 승인 경계

```
Dater 승인 대상 = consent_revisions.scene_definition (불변 JSON) + scene_hash
공개 웹 플레이어 = 승인 revision의 같은 JSON
MP4 워커        = 같은 JSON을 다시 읽고 hash 재검증, 불일치 시 거부
```

현재 구조의 두 결함이 여기서 함께 닫힌다:

1. `PitchPlayer`가 `onLoadedMetadata`로 실제 오디오 길이를 읽어 **재생 시점에 장면 구간을 다시 계산**한다(`apps/web/src/components/PitchPlayer.tsx:159-174`). 승인 시점과 재생 시점이 다를 수 있다. → 런타임 재계산 금지, 오디오 메타데이터는 불일치 **검증용**으로만.
2. consent 화면은 코드 주석부터 "A still preview"다(`ConsentFlow.tsx:1492`). → 같은 장면 JSON을 재생하는 공용 플레이어로 교체.

### 3.4 효과 어휘는 닫힌 union

15종 닫힌 union(kenBurns/punch/parallax/maskReveal/grade/grain/lightLeak/wordPop/kineticText/sticker/progressBar/waveViz/countBadge/speedRamp/backdropBlur).
렌더러가 union 밖 효과를 만나면 plan을 거부한다 → **C2("효과만, 원본 픽셀 유지")가 약속이 아니라 코드 강제가 된다.**
U1에 따라 **제3자 보호용 블러·크롭만 예외**로 추가한다.

### 3.5 음악 없이 리듬 만들기 (C6)

세그먼트 타임스탬프만으로는 부족하다(문장 단위 3~10초). 오디오 분석을 더한다:
`silencedetect` 0.056초 + `astats` RMS 0.080초로 34.5초 녹음에서 휴지 12개 + 강세 온셋 20개 = **컷 후보 32개를 사실상 공짜로** 얻는다.

- `section`(무음 ≥700ms) → 하드 컷 / `phrase`(350~699ms) → 소프트 전환 / `word` 온셋 → 워드팝 / RMS 액센트(+3.5dB) → punch-in
- 철칙: **단어 중간에서 절대 전환하지 않는다.** 컷은 말에서, 액센트는 단어에서.
- IOI 변동계수 0.46 → 말은 템포 격자가 아니라 **이벤트 목록**이다. 사용자가 나중에 얹을 미지의 곡 비트에 미리 맞추는 것은 원리적으로 불가능하며, 시도해서도 안 된다.
- 분석 결과는 반드시 장면 JSON에 **구워 넣는다**. 런타임 재계산하면 C5가 깨진다.

### 3.6 크롭 사다리 — 사진 4장으로 12샷

L0 wide → L1 punch → L2 detail → L3 wide-alt → L4 typographic. 같은 (asset, step) 조합은 3샷 간격.
샷 길이 `MIN 1200 / TARGET 2600 / MAX 4500ms` + **"2500ms 이상 시각 변화 없음 금지"**.
포함된 모든 에셋은 최소 1샷 등장이 필수다.

## 6. 이 트랙과 무관하게 지금 깨져 있는 것 (P0)

**Dater가 고친 문장이 공개 페이지에 반영되지 않는다.**

- 전사 → `structure` JSON → `headline = structure.hook`, `body = relationship_context + evidence_or_anecdote + "A good match: " + good_match_for` (`apps/web/app/api/transcribe/route.ts:154-177`)
- `create_dater_revision`은 고쳐진 headline/body를 저장하면서 **`structure`는 `latest.structure` 그대로 복사**한다 (`0041_dater_profile_and_location.sql`)
- 공개 페이지는 `structure`가 있으면 **`structure`를 렌더하고 `body`는 무시**한다 (`apps/web/app/p/[campaignSlug]/page.tsx:148`)
- 게다가 `three_specific_qualities` 세 문장은 consent 화면에 **아예 표시되지 않는다** — `consentRepo.ts`의 revision structure 스키마가 `hard_claims_requiring_confirmation` 하나만 파싱하고 `ConsentFlow.tsx`는 `structure`를 단 한 번도 참조하지 않는다

그리고 바로 그 아래에 이렇게 적혀 있다 — _"every word here was reviewed and approved by {daterName} before publishing."_

CLAUDE.md §8("공개 전 Dater 개별 승인")과 정면 충돌하며, 코드가 하지 않는 것을 사용자 대면 문구가 주장한다.

## 7. 열린 항목

- **영상 상한 (2026-07-30 확정, U8~U11)**: 클립 **전체 3 · 무료 1 / 프리미엄 3**(scene 자산 12 상한 안에서 사진과 공유) / **원본 ≤15초**(picker `videoMaxDuration`) · **scene 사용 ≤10초** / **인제스트 성공 즉시 원본 삭제**(무음 프록시만 보존, 모더레이션 플래그된 원본만 검토 증거로 예외 보존) / **원본 파일 ≤200MB**(Supabase Pro 전제 — Free면 파일당 50MB 하드캡이라 Pro 전환 전까지 50MB 임시 운영, 플랜 확인은 사용자 게이트). 파생 원가: 모더레이션 $0.098/피치(시각 $0.10/분+음성 $0.03/분 × 45초 원본), 프록시 ≈9.4MB/피치, 열람 무게 사진만 5MB → 3클립 14.4MB(무료 에그레스 250GB = 1.7만 열람)
- **얼굴 감지 실패 시 폴백**(U1의 잔여): 감지 신뢰도가 낮은 클립을 자동 통과시킬지, 사람 검토 큐(U3)로 보낼지. 안전 기본값은 후자이며 Phase 3에서 확정
- **`0044` NULL-digest grandfathering**: 0044 이전 interest 행은 해소 불가능한 사진 경로를 그대로 갖는다. `dating_profiles.photos`와 `storage.objects` 대조 감사 + 백필 전까지 남는 구멍
- **엔타이틀먼트 없는 캠페인 부활**: `0044`의 expired 가드는 결제를 검사하지 않는다. 마이그레이션 주석이 더 이상 검사한다고 주장하지 않으며 테스트 B4가 사실을 보여준다
- **`enforce_message_rate_limit`(0025:27-46)**: 채팅 메시지 카운트에 락이 없어 신고 라우트와 동일한 경합을 갖는다. 이번 범위 밖, 별도 과제로 기록
- **미확인으로 남은 것**: TikTok 공식 safe zone 실측값, Creatomate 가격, Remotion 미설치, 클라우드 벤치마크 미실시. **사용자 대면 문구에 쓰지 말 것**
