# Friendword 냉정한 제품 평가 — 출시 전 마지막 점검 (2026-09-09)

> 근거: 2026-09-08 자율 QA(프로덕션 웹·iOS 시뮬레이터·실제 렌더 MP4 `export2.mp4` 프레임 분석), 저장소 문서, 그리고 출처를 단 외부 조사. 평가는 사용자(MZ, 북미) 관점에서 "이대로 내보내면 어떻게 되는가"를 묻는다. 칭찬은 짧게, 문제는 길게 썼다.

## 0. 한 줄 판정

**제품의 논리(친구 목소리 → 당사자 승인 → 무가입 열람 → 수신함)는 시장 신호와 정확히 맞고, 앱·웹의 신뢰 표면은 이 단계의 인디 제품치고 이례적으로 잘 만들어져 있다. 그러나 성장 루프의 유일한 크리에이티브인 릴스 MP4는 지금 상태로는 틱톡에서 3초 안에 스와이프될 물건이다.** 출시는 해도 되지만, **릴스 결과물을 고치기 전까지 "릴스로 성장한다"는 전제는 성립하지 않는다.** 이것이 출시 전 P0다.

## 1. 릴스 결과물 — 왜 "허접"하게 느껴지는가 (프레임 증거)

실제 음성(40.6초)으로 프로덕션에서 렌더한 MP4(warm 템플릿, 14샷)를 0.3s/1.5s/3s/6s/10s/15s/22s/30s/36s/39.5s에서 잘라 봤다.

| 관찰                 | 결과                                                                      | 왜 문제인가                                                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **첫 프레임(0~2초)** | 사진 1장 + 하단 캡션 카드 "Hi, I'm introducing my friend, Haneul."        | 틱톡 훅 데이터(34,635클립)에서 최고 성과 훅은 **첫 2초에 결과/제품을 보여주는 것**. 우리는 "누가·왜·뭘" 아무 것도 안 보여준다. 이름도, "introduced by"도, 브랜드도 없음 |
| **화면 구성**        | 사진 풀블리드 + 느린 줌(Ken Burns) + 캡션 카드 1개. 40초 내내 동일        | 웹 공개 페이지의 "스테이지 카드"(MAYA INTRODUCES / Blair / 파형 / 칩)는 MP4에 **전혀 없다.** 웹은 브랜드가 있고 MP4는 익명 슬라이드쇼다                                 |
| **캡션**             | 베이지 카드 안 2줄, 문장 단위 교체, 키워드만 주황                         | 2026 틱톡 캡션 관행은 **단어 단위(karaoke) 고대비 자막, 화면 중하단**. 우리 카드는 "자동 생성 슬라이드" 느낌을 주는 가장 큰 요소                                        |
| **세이프존**         | 캡션 카드 오른쪽 여백 ≈120px (안전 기준 140px)                            | 틱톡 우측 아이콘 열이 카드 끝을 덮는다                                                                                                                                  |
| **길이**             | 40.5초 + 엔드카드 1.5초 (60초 녹음이면 61.5초)                            | 음성 전체를 그대로 트는 구조. 틱톡에서 낯선 사람이 정지 사진 위 60초 음성을 끝까지 들을 확률은 낮다(리텐션이 곧 도달)                                                   |
| **파형·리듬**        | 없음(웹에는 있음)                                                         | 음성 콘텐츠인데 "소리가 나고 있다"는 시각 신호가 없다. 음소거 자동재생 환경에서 정지화면으로 보인다                                                                     |
| **엔드카드**         | 검정 배경 + "Friendword" + 주소 텍스트 1.5초                              | CTA로서 약함. QR·"Comment FRIEND"·이름 없음                                                                                                                             |
| **좋은 점**          | 오디오 무손실, 결정론적 렌더, 승인된 것만 들어감, 사진 크롭이 얼굴을 유지 | 파이프라인은 튼튼하다. 문제는 **연출**이지 기술이 아니다                                                                                                                |

**결론**: 지금 MP4는 "친구의 목소리"라는 우리 최고 자산을 **가장 덜 매력적인 형태(정지 사진 + 문장 카드)**로 포장한다. MZ는 이걸 "앱이 자동으로 만든 것"으로 즉시 읽는다(인간 제작 UGC 진정성 81/100 vs AI 생성 63/100).

### 무엇으로 바꿔야 하나 (P0, 개발 필요 — 규모는 "중")

1. **15~30초 하이라이트 컷 기본값**: 전사 세그먼트에서 가장 구체적인 2~3구간(일화·"good match for")을 골라 자르고, 전체 60초는 웹 페이지에서만. 훅은 항상 첫 2초에 **"[이름], introduced by [친구이름]"** 스테이지 타이틀.
2. **스테이지 카드를 MP4에 이식**: 웹 플레이어의 상단 "X INTRODUCES / 이름 / 관계 칩"과 **파형**(재생 중 핑크)을 MP4 상단·하단에 넣는다. 브랜드 일관성 + "소리 나는 영상"임을 시각화.
3. **단어 단위 자막**: 카드 대신 고대비 karaoke 자막(흰/검 외곽선 또는 머스터드), 세이프존(상 130 / 하 484 / 우 140 / 좌 44 px) 준수.
4. **엔드카드 강화**: 이름 + "Approved by [이름]" 배지 + QR + "Comment FRIEND". 2.5~3초.
5. **템플릿 2종(warm/hype) 시각 차이 확대**: 지금은 크롭 속도만 다르다.
6. **(선택, 큰 상방) Introducer 셀피 클립 삽입**: 녹음 화면에서 "말하는 동안 전면 카메라 3초"를 선택적으로 캡처해 첫 컷으로 — 틱톡 문법(사람이 말하는 얼굴)에 가장 가깝다. 동의·초상권은 Introducer 본인이라 단순.

## 3. 잘 만든 것 (짧게)

- **신뢰 구조**: 승인 전 비공개, 원본 음성 무편집, "Approved by" 배지, 신고·차단·삭제, AI 동의 — 이 카테고리에서 드물게 정직하다. 심사와 언론에 강한 재료.
- **디자인 시스템**: 스티커·크림·주황은 데이팅 앱 클리셰(보라 그라데이션·네온)를 피했고 MZ 취향에 맞는다. 다만 **MP4가 이 시스템을 못 받았다**(§1).
- **공개 페이지**: 세로 스테이지 + 파형 + 구조화 문단 + 신뢰 박스 — 페이지는 좋다. 문제는 사람들이 페이지가 아니라 릴스를 먼저 본다는 것.
- **엔지니어링**: 결정론 렌더, 귀속 계측, 가드(무음·이름·길이)가 오늘 밤 다 닫혔다.

## 4. "먹힐까?" — 냉정한 확률 판단 (근거 있는 의견)

- **컨셉 수용(친구 보증·음성·승인)**: 높음. 64%가 친구 추천을 신뢰, 대형 앱이 같은 방향, 틱톡 장르가 이미 있음. 셋로그의 100만 DL도 "알고 시작하는 만남"의 수요 증거.
- **첫 시청 → 페이지 방문**: **낮음(현재 MP4로는)**. 첫 2초에 아무 정보가 없고 정지 사진이다. §1 P0 없이는 릴스 전환 가설(2%)조차 못 검증한다.
- **페이지 → 관심**: 중. 페이지는 좋으나 관심 표현 마찰(계정+프로필)이 크다. 다만 이 마찰은 "진지한 관심만" 필터라 Dater 만족과 맞교환.
- **Introducer 재참여(루프)**: 중~높음. 성공한 소개는 강한 자랑거리라 2차 소개 동기가 있다. 단, 첫 세션 길이(§2)가 병목.
- **매출**: 낮음(현재 SKU로는). 유료 실체가 무료보다 매력이 없다. 릴스 하이라이트·템플릿을 유료로 옮기면 개선.

## 6. 결정 필요 (소유자)

1. **P0 릴스 재설계를 해커톤 창 안에 할 것인가.** 추정 2~~4일(설계 1일 + 구현·테스트 2~~3일). 제출(9/12)과 병행 가능 — 앱 빌드에는 영향 없고 웹 렌더만 바뀐다. 권장: **한다.** 안 하면 릴스 배포를 미루고 페이지 링크 공유(DM·스토리)로만 시딩한다.
2. **유료 실체 이동**(Creator Launch = 하이라이트·템플릿) — 렌더 재설계와 같이 결정.
3. **Introducer 셀피 클립** — 해커톤 후.
